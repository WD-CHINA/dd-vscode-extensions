# 开发规范

这些扩展是本机应用的启动器。实现和文案都按这个边界来。

## 扩展做什么

- 用活动栏、状态栏，以及必要时的资源管理器右键来打开本机应用。
- 不注册快捷键。
- 不在编辑器里嵌入外部应用，也不留常驻子进程。唤起时用 `execFile(...).unref()`，调用结束就松开。
- 只支持 macOS。其他平台和远程窗口给出明确错误，不要尝试打开。
- 应用路径写死在 `/Applications` 下的候选列表里，用 `existsSync` 选择第一个存在的路径。不要依赖用户配置才能启动。
- 界面和错误提示使用简体中文。`displayName`、`description` 和 README 也使用简体中文。

## 命名

- 目录和 `package.json` 的 `name` 用小写短横线，例如 `feishu-launcher`。
- `publisher` 固定为 `dd-vscode-extensions`。
- 命令、视图和状态栏使用同一前缀：`warp.*`、`feishu.*`、`sourcetree.*`。
- 活动栏容器 id 用这个前缀的单词本身，例如 `feishu`。侧边栏视图 id 用 `<前缀>.sidebar`。
- 共享包名是 `@dd-vscode-extensions/shared`，扩展通过 `"@dd-vscode-extensions/shared": "workspace:*"` 依赖它。

## TypeScript

继承仓库根的 `tsconfig.base.json`。模块格式是 `nodenext`，因此：

- `src` 里的相对导入带 `.js` 后缀，例如 `from "./sourcetree.js"`。
- 测试文件由 Node 直接执行，相对导入带 `.ts` 后缀。
- 不要把 `moduleResolution` 改回 `node` 或 `node10`。

`types` 只包含 `node`。`vscode` 通过 `import * as vscode from "vscode"` 解析，不要再写进 `types`。

测试必须能被 `tsconfig.json` 包含，否则编辑器会把它们当成孤立文件，报找不到 `node:test`。测试不能被 `tsconfig.build.json` 包含，否则会进 `out/` 并被打进 vsix。

能脱离编辑器测试的逻辑放到单独模块，例如路径解析、Git 根目录判断。`extension.ts` 只负责命令、界面和唤起应用。

## 界面

- 活动栏图标放在扩展的 `media/*.svg`，单色、用 `fill="#000"`。视图的 `icon` 指向同一个文件。
- 侧边栏是 webview。隐藏后保留页面：`retainContextWhenHidden: true`。
- webview 设置内容安全策略：`default-src 'none'`，脚本使用一次性 `nonce`。不要加载外部脚本或图片。
- 状态栏项放在左侧，点击执行该扩展的主命令。打开过程中可以把文字换成 `$(loading~spin)`，结束后恢复。

## 打包内容

`.vscodeignore` 至少排除 `src`、`node_modules`、`tsconfig*.json`、`*.ts` 和 `*.map`。vsix 里只保留 `package.json`、`readme.md`、`media` 和 `out` 里的运行代码。

不要把 `.vsix`、`out/` 或 `node_modules/` 提交进 git。

许可证是 MIT，正文只放在仓库根目录的 `LICENSE`。每个扩展目录里放一个指向它的符号链接，这样打包时 `vsce` 能在扩展目录里找到许可证。

## README

每个扩展的 `README.md` 会打进 vsix，只写使用者能看到的入口，不写编译和打包命令。仓库级说明放在根目录 `README.md`，开发步骤放在 `docs/`。
